Master VPS Cloud Hosting Handbook

The unified architectural bridge connecting GoDaddy DNS, Caddy Front-Door Ingress Gateway, and native Ubuntu Systemd Backend Daemons on the KeshavSoft server fleet.

🌓 The Two Halves of Cloud Hosting

Cloud application hosting on a production Linux VPS splits cleanly into two complementary halves:

Half 1 • Front Door Ports 80 / 443

Caddy Reverse Proxy & Gateway

Receives incoming public HTTPS requests, issues automatic Let's Encrypt / ZeroSSL TLS certificates, and routes traffic via /etc/caddy/caddy.json.

Tools: caddy-cli • caddy-subdomain • caddy-fileserver
Half 2 • Backend Engine Ports 3000..9328

Ubuntu Systemd Daemons

Runs your Node.js code in /root/KeshavSoft/<app> under kernel-level supervisor units in /etc/systemd/system/ with auto-restart and boot persistence.

Tool: ubuntu-service-cli

🧭 The 3-Stage VPS Subdomain Maturity Model

Never try to configure GoDaddy DNS, Caddy reverse proxy, Node.js ports, and systemd services all in one leap. Follow the 3-stage maturity model:

Stage 1: Smoke Flight Check (Zero Disk / Zero Code)

Verifies that GoDaddy DNS reaches 103.174.102.116 and Let's Encrypt TLS issues a valid certificate in memory: 

npx caddy-subdomain probe call.keshavsoft.com

Stage 2: Static File Server (Real Disk I/O)

Provisions /usr/share/call.keshavsoft.com, writes starter index.html, and configures Caddy's native file_server handler: 

npx caddy-fileserver init call.keshavsoft.com

Stage 3: Full Dynamic Application (Process Supervisor + Reverse Proxy)

When server-side Node.js or REST APIs are needed, bind internal port via systemd and promote the Caddy route: 

# 1. Audit and manage systemd service unit:
npx ubuntu-service-cli check appointment.keshavsoft.com

# 2. Promote Caddy route to forward traffic to localhost:3000:
npx caddy-subdomain add appointment.keshavsoft.com 3000

🚨 502 Bad Gateway Triage Tree

When an active site throws a 502 Bad Gateway, use this exact 30-second triage checklist:

Step 1: Is Caddy or Node.js at Fault?

If Caddy returns the 502 page, Caddy is 100% healthy! The error proves public traffic reached Caddy on port 443, but Caddy found nothing listening on the target internal port. 

# Test internal port directly on the VPS:
curl http://localhost:3000

Step 2: Inspect Systemd Service Unit

# Check systemd daemon status:
npx ubuntu-service-cli check appointment.keshavsoft.com

# Or tail live application console error logs:
journalctl -u appointment.keshavsoft.com.service -n 50 -f
